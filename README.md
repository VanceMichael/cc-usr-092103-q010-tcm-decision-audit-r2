# 方证辅助诊疗审计系统

面向中医（方证对应）辅助诊疗模型在龙华医院各院区、区域医疗中心与医联体
多机构部署的**审计中台**：回答审计人员“同一病例为何在两个模型版本下
得到不同建议”，并对机构权限、患者授权、获准病种、名医经验来源和实际
输入进行**按当时状态的确定性重放**，严格区分模型输出与医生最终处置。

> 全部资料与样例均为虚构，不含真实个人信息、账号或凭据。

## 审计问题如何被回答

`AuditEngine.replay(uid)` 对一次推理请求重建当时的完整决策上下文：

1. **机构权限**：请求机构沿 `总院→院区`、`区域中心→站点`、
   `医联体→成员` 的层级链解析版本登记；
2. **患者授权**：按请求（就诊）时刻校验用途、病种、机构范围、有效期与
   撤回状态，授权文本拍成带摘要的快照；
3. **获准病种**：机构登记的 `disease_scope` 之外一律驳回；
4. **名医经验来源**：每个模型版本固化 `experience_source_codes`
   （如邵长荣、刘嘉湘经验条目）与术语版本、模型清单摘要；
5. **实际输入**：仅保存脱敏后的最少必要特征，请求体带规范化摘要；
6. **模型 vs 医生**：`MODEL_OUTPUT` 与 `CLINICIAN_CONFIRMED/REVISED/
   DISMISSED` 分别建事件，患者端只显示后者。

`compare_versions(uid, ["1.4.0","1.5.0"])` 用同一实际输入在两个版本下
各跑一遍确定性规则，输出方剂、置信度、规则集/阈值/排序策略、经验来源
的逐项差异。示例结论：

| 版本 | 规则 | 建议 | 置信度 |
|---|---|---|---|
| 1.4.0 | 固表优先，阈值 0.5 | 玉屏风散、四君子汤 | 0.8334 |
| 1.5.0 | 健脾优先，阈值 0.6，既往方去重 | 玉屏风散 | 0.7333 |

差异来自**版本规则变更**（1.5 提高阈值、调整君药次序、剔除既往已用且
无效的四君子汤），而非数据被改动——输入摘要与输出摘要都可复算。

## 确定性规则

- **重复请求**：`request_uid` 为幂等键，重试永远返回首次结果，记
  `REQUEST_DEDUP`，不产生第二条建议或事件链分叉。
- **灰度切换**：按 `HMAC(患者化名|新版本)` 取 0–99 桶，桶号 < 百分比才
  进灰度；同一患者永远落同桶，结果可解释、可重放。灰度候选默认不进入
  机构 `allowed_versions`。
- **离线补传**：以实际就诊 `occurred_at` 路由——版本必须在该时刻已
  发布且未停用，不能“后借”新版本。
- **跨院会诊**：禁用灰度，取各方 `allowed_versions` 交集；交集为空或某
  方未获准该病种即驳回。
- **停用条件**：医务处手工停用、严重不良结果达阈值自动停用、授权撤回、
  越病种/越机构均产生驳回或停用结果；停用以 `VERSION_STOPPED` 事件追加，
  历史版本仍保留可重放。

## 不可反向修改的事件

驳回（`REQUEST_REJECTED`）、医生修订/不采纳、不良结果（`ADVERSE_OUTCOME`）、
授权撤回（`CONSENT_WITHDRAWN`）、版本停用、科研导出全部是只增事件。
每条事件含 `prev_hash` 与自身 `hash`，`EventLog.verify()` 重算整条链，
任何插入、删除、改写都会暴露；JSONL 重载时强制校验。

## 隐私边界

- 推理请求只接受术语编码与年龄段等粗粒度特征，身份证/手机号/自由文本等
  在入库前被 `minimize.py` 拒绝；
- 患者端只显示 `confirmed/revised` 的医生最终处置，模型原案、待确认、
  被驳回、灰度未采纳建议均不可见；
- 科研导出须用途授权含 `research`、伦理批件与数据集在 `research_scope`
  内，使用**独立盐值**生成研究化名（与临床化名不可互推），按
  (年龄段, 性别) 做 k-匿名抑制，且每次导出/拒绝都留痕。
